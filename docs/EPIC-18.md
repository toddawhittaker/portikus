# Epic 18: Admin interface polish

This is the working brief for Epic 18. It is the requirement an agent implements against. Where it is silent, `docs/SPEC.md` wins on behaviour (sections 20.1, 22.3, 24.11 and 25.8) and `docs/DESIGN.md` with `design/` wins on looks. It comes from the admin UX review of 2026-09-26 (the git-ignored `screenshots/2026-09-26-admin-ux-review.md` and the `2026-09-26-admin-*.png` screenshots beside it, on Todd's machine).

- **Base commit:** `main` at 3da8d6b. **Epic branch:** `epic/18-admin-ux`. Builders reset to `origin/epic/18-admin-ux` and branch `task/18-<name>` from it.
- **Migrations:** none. No task adds a database migration or a new API route.

## Goal

Make the four admin tabs read as one tidy, width-capped, compact desktop page with the designed table styles, so an administrator's eye can follow a row. Then tidy the Users table, the workspace detail panel, the Audit table and the Settings cards, and add a bulk Rebuild for many workspaces at once.

Closes #600 (item 3, the secondary button border, already landed in #605), #601, #602, #604 and #629. It does **not** close #603 (the Health tab layout): that goes to a later observability epic with the Health charts (#597, #598, #599, #476), which branches from this epic's head.

## Coordination with Epic 20

Epic 20 (student interface polish, #608 and #609) runs at the same time on its own branch and owns the student workspace UI. This epic changes shared files only additively:

- `packages/ui/src/primitives/primitives.css`: T1 appends the Table rules (new classes only). No existing rule, component or prop in `packages/ui` changes.
- `apps/web/src/app.css`: T3 adds the detail-panel classes (and the meter classes if they are missing) in one new block placed directly after the existing `.pk-tag--warning` rule, not at the end of the file, to keep a merge with Epic 20 clean. No existing rule changes.

## Rulings

1. **Width cap.** One inner container in `AdminPage.tsx`, `mx-auto w-full max-w-[1440px]`, wraps the h1, the tab navigation and the tab content. Scrolling stays on `<main>`, so the scrollbar stays at the window edge. 1440 is the mockup's width.
2. **Density.** `data-density="compact"` goes on the admin `<main>`. Compact controls are 28 px high, above the 24 px minimum target size in WCAG 2.2 (SPEC.md 25.8), so nothing needs enlarging.
3. **Desktop only.** The admin area is desktop-only, 1024 px and up (the existing `.pk-root { min-width: 1024px }`). No tablet layout. T1 states this in SPEC.md 20.1.
4. **Table styles are CSS classes, not a React component.** T1 copies `.pk-table-wrap`, `.pk-table` (with its `th`, `td`, hover and `aria-selected` rules), `.pk-num`, `.pk-cell-muted`, `.pk-cell-actions`, `.pk-cell-stack`, `.pk-cell-primary` and `.pk-cell-secondary` from `design/system/components/bundle.css:154-165` and `design/mockups/portikus-screens.css` into `primitives.css`. The sortable-header rules are left out (no sorting in this epic).
5. **Sticky headers work against `<main>`.** The designed `.pk-table-wrap` has `overflow: auto`, which would make the header stick inside the wrap and never against the page scroll. The Users and Audit wraps add Tailwind `overflow-clip`, which keeps the rounded frame but is not a scroll container, so the sunken header sticks to the top of the scrolling `<main>`. No ancestor between the table and `<main>` may be a scroll container (T2 removes the Users table's `overflow-x-auto` wrapper).
6. **One frame per tab, through a small `AdminSection` component.** Four tabs use it, which clears the issue's "three or more places" bar. `apps/web/src/admin/AdminSection.tsx` takes `title`, an optional muted `count` and optional `actions`, and renders a `<section aria-labelledby>` with a heading row (`pk-text-heading` h2, count beside it in `flex items-baseline gap-3`, actions pushed right), then its children (filters row, then content). Nothing else goes in it.
7. **Heading levels.** h1 "Administration" stays (the build keeps the tab navigation under it, as the review recommends). Each tab's name is an h2 through `AdminSection`. Headings inside a tab (Health cards, Settings cards) drop to h3. The detail panel's name drops from h2 to h3 and its section headings from h3 to h4.
8. **Tab titles.** The browser title names the tab: `usePageTitle(\`${TAB_LABEL[tab]}, Administration\`)`, giving "Users, Administration, Portikus". The tab headings are "Users", "Audit", "Health" and "Settings", matching the navigation.
9. **Tabs lose their outer card.** Audit's outer `pk-card` goes; its table sits in a `pk-table-wrap` frame. Health and Settings keep one card per group, under h3 headings. Users never had one.
10. **Health in this epic is frame and table classes only.** T1 wraps Health in `AdminSection`, demotes its card headings, applies `pk-table-wrap`/`pk-table` to its tables and `pk-num` to its counts. The three-row layout, state badges, the warning-coloured pool tag and chart styling are #603 and stay untouched.
11. **Users columns.** Checkbox, Account, Role, Workspace (label and state badge), Last activity, Image, Connections. Source, Last sign-in and Storage move out; the detail panel already shows them and T3 confirms it. The Account cell is two lines (`pk-cell-stack`): name with markers, then email, or the username when there is no email. The Image cell is empty when the image is current or unknown, and shows `pk-tag pk-tag--warning` "Older image" (the word the Image filter uses) when it is out of date, with the image label in `title`.
12. **Users count** ("13 accounts · 4 running") moves to the heading row's count; "Add user…" moves to its actions. "Showing 12 of 13" stays at the end of the filters row.
13. **Filter row alignment.** The "Show archived" checkbox and the "Showing N of M" count each sit in `flex h-[var(--pk-control)] items-center` inside the `items-end` row; no margin nudges.
14. **Buttons beside a field that can show an error** (only the Audit filter row after this epic) align to the input, not to the field's bottom: the button group is `self-start` with a top margin equal to the label line height plus the field gap (`mt-6`, 18 px + 6 px, from `LABEL_CLASS` and `FIELD_CLASS`), with a comment naming those two constants. This keeps `TextField` in `packages/ui` unchanged. Settings has no such row once every Save moves below its fields.
15. **Settings.** Cards in `grid grid-cols-[repeat(auto-fill,minmax(420px,1fr))] gap-6` (cards drop `max-w-160` and their `mt-6`). Every Save sits in its own `pk-actions` row below the fields. Numeric inputs are all `w-48`; the Resource guard inputs sit in `grid grid-cols-[repeat(2,max-content)] gap-x-4 gap-y-3`.
16. **Detail panel.** Port `.pk-detail-head`, `.pk-detail-section` and `.pk-dl` from `design/mockups/portikus-screens.css:193-196` into `app.css`, and the `.pk-meter*` rules (lines 158-167) only if the existing `StorageMeters` does not already have equivalent styles. The panel keeps its 400 px width and its `pk-card` frame (the `.pk-detail` rule's width and flex are not needed). It is `sticky top-0 self-start max-h-[calc(100vh-<header>)] overflow-auto`, with the header height measured, not guessed.
17. **Detail panel order.** Head (name, state badge, Start, Stop, Restart directly under the badge, the close button), then one section each, in this order: Error (only when there is one), Account (source, last sign-in, username, email, Disable), Workspace (image, Rebuild, Reset Docker, Archive, grace override), Storage (with "Edit quotas…" in its heading row, a `pk-dl`, and the existing meters with their text kept for screen readers), Resource guard, Ports and connections, Logs, Recent audit. An empty slot for #595's process list is not built; that issue adds its own section.
18. **Audit IDs.** Actor and Target IDs show their first 8 characters in `pk-mono-small`, with the full ID in `title` and as the accessible name (`aria-label` on the link or a visually hidden full value). Names still win over IDs where the API gives one (`actorName`).
19. **Audit time.** The Health tab's short format (`HealthTab.tsx:272`), moved to a shared helper in `apps/web/src/admin/` if both tabs use it, inside `<time dateTime>` with the full `toLocaleString()` in `title`.
20. **Audit result.** A `pk-tag`: "ok" and "success" neutral; "denied" and "failure" (and any other value) in the `status-error` soft colours via a new modifier `pk-tag--error` added next to `.pk-tag--warning` in `app.css`. Only T4 adds this one rule, so it does not collide with T3's block.
21. **Audit details** cap at `max-w-[48ch]`, one line per key with `truncate`, the full value in `title` and in a visually hidden span so screen readers read all of it.
22. **Audit target links set the target filter.** The API's `workspace` filter is an exact match on the target, whatever kind it is, so the link fills that filter and applies it. The field is relabelled "Target ID" because that is what it filters; the URL key stays `workspace` so old links work.
23. **Audit actor names (#600 item 7).** T4 confirms with a test that every `user:<id>` actor resolves to a name; the review's raw IDs came from seed data that wrote actors without the `user:` prefix. If a real code path writes a bare user ID as actor, T4 fixes that path.
24. **Bulk Rebuild reuses the existing single-workspace route from the browser**, one request at a time, as the Epic 13.1 bulk actions already do (`WorkspacesTab.tsx` `BulkActions`). No bulk endpoint: each request already writes its own `workspace.rebuild_requested` audit row with the administrator's session, refuses a pending operation with 409, and is administrator-only and CSRF-checked. Rejected: a new bulk API route, which would duplicate that logic for no user-visible gain.
25. **Bulk Rebuild targets** accounts with an unarchived workspace. A 409 answer (`OPERATION_PENDING` or `OPERATION_IN_PROGRESS`) counts as **skipped**, any other error as **failed**.
26. **Bulk Rebuild dialog** says how many workspaces, names those that are running (they restart), offers "Also reset Docker" (off by default), and carries the same warning as the single Rebuild dialog (SPEC.md 22.3: system packages installed with `sudo apt` are lost; home, projects and Docker data stay unless Docker is reset). It reuses the existing `ConfirmDialog` and the single dialog's copy.
27. **"Rebuild all on older images…"** appears in the Users heading actions only while the Image filter is Older, and opens the same dialog with the shown rows whose image is out of date and whose workspace is not archived.
28. **Bulk Rebuild progress** uses the existing inline `bulk-result` status region, with done, skipped and failed lines, not a toast, to match the other bulk actions. Rows leave the Older filter on the list's existing refresh (`ADMIN_REFRESH_MS`); no new polling. The worker's concurrency is unchanged (#614 covers stalls).
29. **Screenshots.** Each visible task saves screenshots of the tabs it changes at 1920 and 1280 px in both themes to `screenshots/` (git-ignored), named `2026-09-2x-epic18-<task>-<screen>-<width>-<theme>.png`, and lists the paths in its PR. The epic PR links the full set.

## Verification

- **Every task:** `pnpm typecheck`, `pnpm lint`, `pnpm test:coverage` above the floors, `pnpm build`, and `pnpm test:e2e` against a fresh test database, before its PR. Existing admin unit and e2e tests are updated to the new layout, never deleted to pass.
- **T1 unit:** `AdminSection` renders the heading, count and actions; `AdminPage` sets the per-tab title and the density attribute. **T1 e2e:** at 1920 px the content container is at most 1440 px wide; each tab shows an h2 naming it; `<main>` has `data-density="compact"`; the Audit table header stays in view after scrolling `<main>`; a secondary admin button's computed border colour is not transparent.
- **T2 unit:** Account cell lines, Older image tag only when out of date. **T2 e2e:** the Users table has exactly the seven column headers; the header stays in view after scrolling; the checkbox and count are vertically centred on the controls' row (bounding boxes); the table has no horizontal scroll at 1280 px with the detail panel open.
- **T4 unit:** ID shortening, the short time format, result-to-tag mapping. **T4 e2e:** short IDs with the full ID in `title` and in the accessible name; clicking a target filters the table to that target; ok, denied and failure show as tags with the right classes; the Apply button's bottom equals the input's bottom with and without an ID error shown.
- **T5 e2e:** the Settings tab heading, a grid of cards, Save below its field in every card (Save's top is below the field's bottom), guard inputs 192 px wide.
- **T3 unit:** section order and headings, "Edit quotas…" in the Storage heading. **T3 e2e:** at 1920 by 1080, Start, Stop and Restart are visible without scrolling the panel; with a long Users table scrolled, the panel stays in view; every section heading present; Tab order runs head, actions, then sections; opening the panel still moves focus to its heading.
- **T6 API test** (`maintenance.test.ts`): two workspaces rebuilt in turn each get their own `workspace.rebuild_requested` row with the administrator as actor; a request without CSRF headers is refused; the existing admin-only and pending-operation tests stay. **T6 unit:** target selection, skip and failure classification, dialog copy with and without running workspaces. **T6 e2e:** select two accounts, bulk Rebuild, confirm, both workspaces get the pending operation, and the summary lists done and skipped; with the Image filter on Older, "Rebuild all on older images…" offers exactly the older rows.
- **Screenshots** per ruling 29. **a11y-reviewer** over the epic: heading order, the truncated audit text staying available to screen readers and keyboard users, the bulk Rebuild dialog, focus in the sticky detail panel, compact target sizes, and one line confirming the secondary button edge contrast in both themes (from #605).
- No infrastructure changes, so no rehearsal VM.
